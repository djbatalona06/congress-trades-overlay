# PRD delta, 2026-10-13

This is the main spec for version 1.1.0. It sits on top of `2026-10-07-congress-trades-overlay-spec.md`. Sections 9 and 10 at the end record what was built and how it was checked.

## 0. What changes

- **Header menu:** the popup gets a top bar with the brand, the Free/Pro badge and three tabs. Each tab shows one section. Only one section is visible at a time, so the 340px popup stops scrolling through everything.
- **Account:** the Plan tab shows real status, when it was last confirmed, and one action for each state. A failed check says so, instead of failing silently.
- **Paywall parity:** price, free limit and Pro features come from one set of constants. A test fails if the store listing drifts from them.
- **Accessibility:** WCAG 2.2 AA for the whole extension, AAA for contrast and target size. Keyboard-only use works in the popup and the panel.
- **Broker links on the site:** a row of links to each broker's company website (TradingView, Robinhood, Webull, Charles Schwab, and Interactive Brokers / IBKR), so visitors can open their existing broker or start a new account. Only the first four are supported by the extension (see 3.6).
- **Out of scope:** new analytics (it would change the store's data-use disclosure), a logout button (confirm ExtensionPay supports it before adding one), Safari, i18n, rendering Worker bill data in the panel, and any change to the disclaimer text.

## 3. Technical design

Stack stays as it is: WXT 0.21, React 19, plain CSS, Vitest. New runtime cost: $0. New dev dependency: `axe-core` only.

### 3.1 Single source for plan facts (G4)
`PRO_PRICE_MONTHLY = 8` sits next to `FREE_WATCHLIST_LIMIT` in `lib/watchlist.ts`. Code that prints the price reads the constants. Markdown and HTML copy stays hand-written; a test enforces it (4.2).

### 3.2 Header menu (G1)
Tab bar inside `<header>`: `<nav aria-label="Popup sections">` with a `role="tablist"`. Three `role="tab"` buttons: Watchlist, Plan, Lookups, each with `aria-controls` and `aria-selected`. One `role="tabpanel"`. Keyboard: Left/Right move focus and selection, Home/End jump to the ends, Tab leaves the bar, roving `tabIndex`. Default tab is Watchlist; the selected tab is not saved. The Pro/Free badge stays in the header on every tab.

### 3.3 Account and Pro status (G2, G3)
`refreshPro()` returns `{ ok: true, paid, checkedAt }` or `{ ok: false, cachedPaid, checkedAt }`. Plan tab by state:
- Pro, confirmed: "Pro is active. Last checked {time}." Button: Manage subscription.
- Free, confirmed: Upgrade to Pro (primary) and Already paid? Log in.
- Check failed, cached Pro: "Couldn't reach the payment server. Showing Pro from {time}." Button: Try again.
- Check failed, no cache: "Couldn't check your plan. Check your connection and try again." Button: Try again.

Try again calls `refreshPro()` and redraws; it opens no page. The 72 h grace period in `lib/pro.ts` stays. Logout is not part of this spec.

### 3.4 Accessibility (G5 to G8)
| Item | Change | Target |
|---|---|---|
| Text contrast | `--muted` at least 7:1 on both `--bg` and `--bg-raised` | AAA 1.4.6 |
| Control borders | `--control-border` at 3:1 for inputs and buttons; `--border` stays for decorative lines | AA 1.4.11 |
| Target size | 44x44 CSS px minimum for every popup button, tab and the panel toggle; use padding | AAA 2.5.5 |
| Focus | 2 px outline at least 3:1 against both backgrounds | AAA 2.4.13 |
| Motion | `@media (prefers-reduced-motion: reduce)` turns off transitions and animation in both stylesheets | AAA 2.3.3 |
| Status messages | Add-to-watchlist errors and Pro status changes go in a `role="status"` live region | AA 4.1.3 |
| Panel controls | Keep `aria-expanded` and `aria-pressed`; close button has an accessible name | AA 4.1.2 |

### 3.5 Shipping checks (G9)
One workflow, `.github/workflows/ci.yml`, on pull requests: `npm ci`, `npm run compile`, `npm test`, `npm run build`, `npm run build:firefox`. `npm run zip` only on tags. `deploy-site.yml` stays as it is.

### 3.6 Broker links on the site
In `site/index.html`: a new "Already have a broker?" row after the supported-platforms strip, and the footer's Platforms list. Company home pages only: tradingview.com, robinhood.com, webull.com, schwab.com, interactivebrokers.com. Each link opens in a new tab with `rel="noopener noreferrer"` and a screen-reader note "(opens in a new tab)". No affiliate codes, tracking parameters or redirects. The four supported brokers say so. IBKR is labelled "listed for convenience only; not supported by the extension yet" (supporting it needs a new module in `lib/platforms/` and new host permissions, which is a separate task). Before launch, check each link once in a browser. If affiliate programmes are ever joined, disclose them on the site; none are included now.

### 3.7 Dual-display layout that leaves the chart clear (G12, F2)
Two parts, shipped together.
- **A. Edge tab by default.** The panel collapses to a 28px tab on the right edge, vertically centred, showing the ticker and count (for example `NVDA 5`). Expanding opens the existing 380px panel as a drawer; it closes on Escape or the close button. Users who already saved an `overlayExpanded` choice keep it. Only users who never set it get the edge tab.
- **B. Pop-out window for a second monitor.** A "Pop out" button opens `entrypoints/panel/` as a separate window (`browser.windows.create`, type popup, 380x720). It reads the current ticker from `local:currentTicker`, which the content script writes on each symbol change, using the same `storage.watch` pattern as the watchlist. Its size and position are saved on `pagehide` and restored on the next open; if the saved position is off-screen it opens at the default. It reuses `TradeRow` and the lookup logic from a shared module.
- **Not doing:** resizing or pushing the host page's layout. It is fragile across four broker sites.

### 3.8 Update gate (G13, F3)
Browsers update the package on their own schedule; the extension cannot force it. The gate tells the user what changed before they rely on the data.
- Record `local:lastSeen = { version, at }`, written on first install and whenever the user taps Continue.
- Show the gate when the installed version differs from `lastSeen.version`, or when `now - lastSeen.at` is more than 14 days (`GATE_IDLE_DAYS`).
- A card at the top of the popup with the version, a short "What changed" note and the data status. In the panel, the edge tab gets a small dot until acknowledged; its tooltip says "Update notes: open the Capitol Tape popup". The panel never shows the card.
- Buttons: Continue; Check for updates (Chrome only, `browser.runtime.requestUpdateCheck()`: "You have the latest version" or "An update is ready. Restart Chrome to finish."; hidden on Firefox).
- `RELEASE_NOTES` keyed by version in `lib/update.ts`; a missing entry shows "See the store page for what changed".
- `shouldShowGate(now, lastSeen, currentVersion)` is a pure function.
- Not in scope: a server-side version check or push notifications (they would need a new host permission and service).

### 3.9 Site copy matches real behaviour (G10, F1)
- `site/index.html`: "No sign-up, no API key." becomes "No sign-up. A free Bargo key is optional and raises your daily lookups." "No account required" stays.
- Panel limit message: "Daily free limit reached. Resets at midnight UTC. Add a free Bargo key in the popup for more." Link to the popup's Lookups tab. Confirm the reset time in `lib/budget.ts` before writing "midnight UTC"; do not state a time the code does not use.
- Every place that asks for a key links to `https://www.bargo.ai/connect`: the panel's limit message, the popup's Lookups tab, the site copy, and the README section "Do I need a key?". It is the only key link used.

## 4. Tests
1. **Tab keyboard behaviour** (`tests/popup-nav.test.tsx`, jsdom): Right goes to Plan; End goes to Lookups; `aria-selected="true"`; the panel's `aria-labelledby` points at the active tab.
2. **Parity** (`tests/parity.test.ts`): `CHROMEWEBSTORE.md`, `README.md` and `site/index.html` each contain `$${PRO_PRICE_MONTHLY}/month` and the free-limit wording. Fails with the file name.
3. **Contrast and axe** (`tests/a11y.test.tsx`): WCAG contrast of `--muted`, `--control-border` and the focus colour against each background (7:1 text, 3:1 non-text); render the popup and run axe-core with the `wcag2aaa` tag; exceptions in one array with a reason each.
4. **Pro state:** with the ExtPay call mocked to throw, `refreshPro()` returns `ok: false` with the cached value and time; with no cache, `cachedPaid: false`.
5. **Manual, once before submission:** load the unpacked build in Chromium, click through all four sites, the popup tabs with the keyboard only, and the Plan states with ExtensionPay in test mode.
6. **Update gate** (`tests/update.test.ts`): true for a changed version, true after 14 idle days, false for the same version within 14 days, false with no record (the caller writes one).
7. **Site copy** (in `tests/parity.test.ts`): the site does not contain "no API key" and does contain the optional-key wording; README, site and popup Lookups tab contain `bargo.ai/connect`.
8. **Dual display, manual:** on a two-screen setup, pop out the panel to the second screen, change symbol on the chart, confirm the pop-out follows. Close and reopen the browser, confirm the pop-out returns to its saved position.

## 7. Risks
- Lighter muted text could clash with a visual design preference. It is one token; check the screenshots before submitting.
- 44 px targets make the popup taller. The 340px width stays; the Watchlist list may need scrolling. Accepted.
- axe-core may report false positives inside Shadow DOM. Keep exceptions listed, not silenced.
- Bargo licence and 5 U.S.C. 13107(c)(1) remain the largest risk to the paid tier. No code change removes it. See `bargo-and-this-project.md`.

## 9. What was built, and where it differs from the text above

Scope chosen for this build: all phases A to I, with the on-chart display staying on the four supported brokers (no "any website" detection, no new permissions).

| Topic | Spec said | Built | Why |
|---|---|---|---|
| Limit message (3.9) | "Resets at midnight UTC" | "Daily free limit reached. Get a free Bargo key, then paste it in the Capitol Tape popup (Lookups tab) for more." No clock time | `lib/budget.ts` says Bargo's real reset time is undocumented, and the spec says not to state a time the code does not use |
| Link to the Lookups tab (3.9) | Link to the popup's Lookups tab | The message names the tab; the link goes to `bargo.ai/connect` | A web page cannot open the extension popup on a chosen tab |
| Panel bar text | "(limit reached)" replaced by the full message | The bar says "(daily limit reached)"; the full message is in the opened panel | The full sentence does not fit in the 320px bar |
| README (3.9) | Section "Do I need a key?" | Section added | It did not exist |
| Edge tab size (3.7) | 28px tab | 28px visible, 44px wide button (16px transparent hit area) | Keeps the AAA 44px target rule from 3.4 |
| Edge tab storage (3.7) | Existing choice kept | `getOverlayExpanded()` returns `null` for "never chosen". Opening and closing the drawer saves nothing, so the user stays on the tab | Matches "only users who never set it get the edge tab" |
| Update gate for existing users (3.8) | No record means no gate | On an update with no record, install code writes one with the *previous* version, so the gate shows once | Otherwise the people updating from 1.0.0 would never see it |
| Update dot (3.8) | On the edge tab | Also next to the title in the saved bar | Users with a saved choice have no edge tab |
| Pop-out position (3.7) | Saved on `pagehide` | Also checked every 3 seconds when it changed; off-screen check is a sanity test and the browser moves hidden windows into view | `pagehide` can be missed on close; avoids an extra display permission |
| Colours (3.4) | Lighter `--muted`, 3:1 borders | Also lighter green and red text (`#4ade80`, `#fca5a5`) and darker party badges (`#1e40af`, `#991b1b`, `#475569`) | Needed for 7:1 on text |
| Version | none | 1.0.0 to 1.1.0, release note in `lib/update.ts` | The gate needs a version to announce |
| Parity test (4.2) | contains `$8/month` | Tags are stripped first, and every `$N/month` in a file must match | A single drifted price in a file with two prices was not caught by "contains" |
